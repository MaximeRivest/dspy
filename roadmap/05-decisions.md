# Decision Log

Dated, one entry each, with the why. This is the don't-relitigate file: reopening one of these requires new evidence, not new taste. Append at the bottom; never rewrite history.

- **D-001 (2026-06)** — **The IR is the one-way door.** Representation becomes data inside core; every API tier above it is a two-way door. *Why:* presets/auto-adapter/explain become export decisions, not rewrites.

- **D-002 (2026-08-05)** — **TwoStep compiles away; never an adapter.** Expands to main Predict + frozen extraction Predict. *Why:* component 4 is pure by contract; an LM call in parse is a smuggled binding (invisible to placement census, credentials, cost attribution).

- **D-003 (2026-08-05)** — **Lowerings are a named category** (surface tree → core tree; four laws: interface-preserving, call-honest, provenance-total, composition-as-nesting). *Why:* the "type between modules and adapters" needed a home; CoT was already one.

- **D-004 (2026-08-05)** — **The single-shot law** (one adapter entry = one exchange). *Why:* without it, scores depend on calls the manifest never states.

- **D-005 (2026-08-05)** — **The signature is sacred; exhaust → `_trajectory`.** Prediction fields = declared outputs exactly. *Why:* depending on `result.reasoning` couples programs to the mechanism that answered. Litmus: want it? declare it.

- **D-006 (2026-08-05)** — **Bracket access does not shim exhaust; dot access does (with DeprecationWarning).** *Why:* one strict contract view must exist; the friendly view warns.

- **D-007 (2026-08-05)** — **ReActV2 included in the exhaust migration** (`history`, `termination_reason`). *Why:* same exhaust class; excluding it enshrines v1/v2 inconsistency.

- **D-008 (2026-08-05)** — **MultiChainComparison is an aggregator, not a lowering.** *Why:* it adds an external input (`completions`), which no lowering may do; it honestly declares its contract.

- **D-009 (2026-08-05)** — **Roles/strategies/codecs: adapter types split into shape + semantic role; strategies per role in component 4; codecs per shape.** *Why:* the types conflated data with inference semantics — the reinvents-typing and can't-drop-the-types complaints resolved independently.

- **D-010 (2026-08-05)** — **Role vocabulary grounded in the typed LM contract.** A role exists iff ≥2 materially different strategies, one escaping the token stream; textual strategies are polyfills; the vocabulary version-tracks the contract, never a provider.

- **D-011 (2026-08-05)** — **Role syntax: `Annotated` markers are the primitive; four spellings, one registry object** (`Annotated[str, X]` canonical; `X[str]` sugar; `@X` string shorthand; `role=` kwarg). *Why:* role must vary independently of shape; `Annotated` is type-checker-transparent and works in every surface incl. FunctAI. Conflicting spellings refuse loudly.

- **D-012 (2026-08-05)** — **Unions with mixed role markers derive `plain`** (explicit `role=` overrides; upgrade silence to an info log later). *Why:* either-of-two-semantic-types as data is legal; guessing is worse.

- **D-013 (2026-08-05)** — **Seeds: per-leaf objective declarations** (frozen / semantics-fixed / metric-driven), user-picked at tag time. Semantics-fixed is code→code only; blooming requires the View-2 cost regularizer default-on; optimizer-authored code carries `authored_by`.

- **D-014 (2026-08-05)** — **Upstream #10119 (interpreter callbacks) safe to accept; five-point orthogonality check adopted** for upstream syncs. Callback plumbing is View-2's polyfill: kill-by-absorption, not conflict.

- **D-015 (2026-08-05)** — **lm15 adopted as the engine's LM substrate.** Component 8a's contract becomes a veneer over lm15 `Request`/`Response`/`StreamEvent`; in-repo parallel types and litellm retire over the arc. *Why:* part vocabulary independently confirms the role projection; contract-governed, zero-dep, cross-language, streaming solved (role-typed deltas). Sequenced after Epic D.

- **D-016 (2026-08-05)** — **Campaign order: D (serializer) → E (lm15) → F (engine) → G (runtime) → H (deletion).** *Why:* D has zero LM-layer dependency; the veneer deserves its own design pass; the engine needs D's serialization and E's contract.

- **D-017 (2026-08-05)** — **Strategy registry and codec seam stay engine-private until Epic D.** *Why:* public shapes get designed deliberately with the serializer, not leaked incrementally.

- **D-018 (2026-08-06)** — **The literal table's full form is a template; an adapter is a preset** `{template, parser, codec bindings, strategy bindings, config}`. Proof: `dspy-template-adapter` reproduces exact ChatAdapter message parity declaratively; its slots map 1:1 onto the IR (`{instruction}`=3a, `{demos()}`=3b, directives=plan slots, `{inputs(style)}`=codecs). Constrained template language, not general Jinja. The 7-key vocabulary survives as a derived summary view. Class adapters = thin constructors over presets; the `format_*` method zoo = legacy override surface, deprecate in D, delete in H. Templates must be strategy-aware (natively-served roles render no block).

- **D-019 (2026-08-06)** — **BAML is a codec, not an adapter.** Preset `json` + {indented-pydantic input, schema-prose schema} codec bindings ≡ today's BAMLAdapter bytes; the class becomes a compat shim. *Why:* Epic B already proved BAMLFormat = JSONFormat + input-codec; this completes the reclassification user-visibly.

- **D-020 (2026-08-06)** — **The adapter layer gets its own contract spec** (`roadmap/adapter-ir-spec.md`): signature core, template language, presets, vocabularies, ADP-001..011 invariants, corpus-based conformance — lm15-structured, provisional until Epic D proves it, then graduates to its own contract repo. *Why:* a frozen conformance surface and a moving design doc cannot share a document; the ProgramIR consumes it by reference exactly as it consumes lm15.

- **D-021 (2026-08-06)** — **Standalone library: yes, later; import boundary: now.** The render/parse layer extracts to its own library (any frontend: dspy/FunctAI/dicts; any backend: lm15 reference, litellm/SDK alternates) AFTER D/E stabilize — the Instructor/BAML market proves the demand, FunctAI-without-dspy is the utility test. Until then, Epic D builds inside `_engine/` under a mechanically-enforced import boundary (engine imports only signature core + types + lm15; never settings/modules/clients) so extraction is a move, not a surgery.

- **D-022 (2026-08-06)** — **Cross-language receivers rung-walk; bake degrades to declare.** A foreign-language engine (Go/TS) treats a component whose rung 0 bakes host-language source as an *unsatisfiable rung* and walks it outward: existing endpoint binding → self-materialized sidecar from the language's env block → loud refusal naming component + language. Recorded as a **re-placement** (a binding/placement change, not an identity deviation — §e0-binding's detach rule does not apply). *Why:* identity is what scores attach to and placement is the receiver's, so the walk preserves warranted scores; the tree needs no walk (closed §d grammar, designed language-neutral — operational semantics pinned during the port campaign; leaves polyglot by placement). Keeps the cross-language goal soft — no Starlark re-evaluation triggered.

- **D-023 (2026-08-06)** — **The declared-tier profile is a named conformance class, defined by binding mode.** Declared LMs (lm15), builtin presets/codecs/strategies, templates-as-data, no authored-origin code, no rung-0 weights; interpreter/tools at receiver-bound endpoint rungs (never in-process, never loader-materialized) or absent; declared-LM `lm.class` blocks are advisory to a profile engine (entry served via its own lm15 client after identity verification, recorded as a binding substitution). *Why:* L5 forbids silent partial support, so a foreign engine's honest subset must be named to be legal — and it is the v1 target for any port. The same predicate at export time is the author's portability preflight.

- **D-024 (2026-08-06)** — **Artifacts are versioned: `ir_version` + a `versions` block for every closed vocabulary and consumed contract** (roles, strategies, codecs, node_set, adapter_ir, lm15) in `manifest.json`, and a matching `versions` block in preset serde; load refuses unknown majors loudly naming both versions, and refuses a missing block as malformed (no unversioned grandfathering). *Why:* every vocabulary is "closed and versioned" in prose but no field existed; without it forward-compat refusal (L5) is unimplementable and every extension is silent drift across engines. Byte-shape change — must precede the exporter (D-γ).

- **D-025 (2026-08-06)** — **Packaged and authored code carry `language`; component 9 generalizes to one env block per language present.** PEP 723/uv is the Python instance; ts → package.json+lock, go → go.mod. Foreign blocks are declared system deps (the toolchain) to the receiving engine; `rat`'s runtime.yaml (detect; install with nested check_env + smoke) is the candidate neutral block schema. Compiled authored languages (Go) are packaged-or-refused until a portable target (WASM) is ratified — deliberately deferred. *Why:* implicit-Python is the one assumption a cross-language receiver cannot afford; also a byte-shape change that must precede the exporter.

- **D-026 (2026-08-06)** — **Authored adapter code does not rung-walk; templates-as-data are the portable customization path.** Foreign engines refuse foreign authored codecs/strategies/parsers at the profile level; evaluating them out-of-process (sound because ADP-002 purity) is an optional engine upgrade, never an artifact requirement. *Why:* component 4 carries no placement by law; this closes the one hole in D-022 without weakening adapter purity.

- **D-027 (2026-08-06)** — **Sidecar wire contracts: candidates recorded as reference behavior; text deferred to E/F.** Interpreter rung: `rat`'s kernel protocol (~/Projects/rat, KERNEL-PROTOCOL.md) as base — needs per-call vars marshaling in/out, typed error codes, version negotiation, auth. Tool rung: MCP with `outputSchema`/`structuredContent` REQUIRED for identity verification (all three in-house MCP bridges — mcp2py, mcptocli, rat — currently drop return schemas). Credential seam: `mcptocli`'s `bearer_env` pattern ≡ `credential_ref`, proven in Go. **MCP sampling is a smuggled LM binding**: a sidecar tool that samples declares that LM as its own binding or the engine refuses the request — lawful-if-declared per the §d network-leaf rule (the representation layers must lower; leaves declare); elicitation and roots are receiver-side UX surfaces needing no declaration. *Why:* the contracts now have working in-house drafts; freezing text before E/F would violate fix-spec-first.

- **D-028 (2026-08-06)** — **The ProgramIR is the product; ports target the IR, not the framework.** Hub-and-spoke: frontends produce IRs, engines execute them, optimizers are IR→IR with a score, evals are IR→score — all periphery, plural and disposable; the IR is the one stable center and dspy-Python is reference implementation #1, not the definition. Two grades per language: **grade 1 — hold** (parse/validate/version-check/link-check/diff/explain; a pure data library) and **grade 2 — execute** (adapter engine + lm15 + node-set interpreter). An optimizer needs only grade 1 plus an execute oracle *somewhere* — checkpoint = save makes propose→score→keep engine- and language-agnostic; scoring may be remote. Consequence: a third contract repo, **programir-contract** (manifest JSON Schema, forward-AST encoding with written operational semantics, link/load/refusal error codes, versions block, artifact corpus seeded by D-γ), is a first-class deliverable atop lm15-contract and the adapter-ir contract; grade-1 TS/Go libraries start the moment it exists; frontends are deferred indefinitely. *Why:* the same play that produced conformant lm15-go/ts, run at the top of the stack; it collapses the 3×3 author×engine matrix (every cell goes through the IR) and answers cross-language.md's posture question.

- **D-029 (2026-08-06)** — **Four manifest-schema rulings from the examples audit.** (1) **One entry per LM**: an LM pool entry is one object holding identity, placement, and (if baked) its weights nested inside — the 12–15 `8_lm` form; the spec's 8a/8b remain conceptual rows, not manifest keys. (2) **Interpreters are named pool entries** (usually one, e.g. `main`); interpreter leaves carry a `ref` — one word now, no breaking change later. (3) **`engine` exists only on baked entries** — a remote server's engine is its own business, not program identity. (4) **`served_aliases` is an optional evidence hint**; `weights_identity` is the required truth (example 09 is the aliases-absent fixture). *Why:* the audit found the examples and the spec table diverging on all four; each is a byte-shape fork the schema cannot be authored without.

- **D-030 (2026-08-06)** — **C1 partial ratification: the D-019 as-built reading stands; no upstream sync before Epic E.** The BAML pairing is codec-owns-spelling / template-owns-arrangement (recorded in adapter-ir-spec §4) — the original "preset json + baml codec bindings ≡ BAMLAdapter bytes" letter was unimplementable because the system-section arrangement is literal-table territory, which cannot lawfully hide inside a shape-generic codec. Upstream sync is deferred past the start of Epic E. Public-name ratification pending against `roadmap/public-surface-epic-D.md`.

The ten-persona evaluation requested no renames (`roadmap/design-eval-epic-D.md`); its two naming-adjacent actions — exporting `PresetAdapter`, and ruling the `parser` (entry key) vs `parse_mode` (constructor kwarg) split — are assigned to the D-δ fix wave, which is authorized on the twelve high-impact defects. *Why:* freezing the names lets Epic E and external adopters build on a stable surface; the defects are semantics beneath stable names and have their own wave.
