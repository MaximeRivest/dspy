- **D-022 (2026-08-06)** — **Cross-language receivers rung-walk; bake degrades to declare.** A foreign-language engine (Go/TS) treats a component whose rung 0 bakes host-language source as an *unsatisfiable rung* and walks it outward: existing endpoint binding → self-materialized sidecar from the language's env block → loud refusal naming component + language. Recorded as a **re-placement** (a binding/placement change, not an identity deviation — §e0-binding's detach rule does not apply). *Why:* identity is what scores attach to and placement is the receiver's, so the walk preserves warranted scores; the tree needs no walk (closed §d grammar, designed language-neutral — operational semantics pinned during the port campaign; leaves polyglot by placement). Keeps the cross-language goal soft — no Starlark re-evaluation triggered.

- **D-023 (2026-08-06)** — **The declared-tier profile is a named conformance class, defined by binding mode.** Declared LMs (lm15), builtin presets/codecs/strategies, templates-as-data, no authored-origin code, no rung-0 weights; interpreter/tools at receiver-bound endpoint rungs (never in-process, never loader-materialized) or absent; declared-LM `lm.class` blocks are advisory to a profile engine (entry served via its own lm15 client after identity verification, recorded as a binding substitution). *Why:* L5 forbids silent partial support, so a foreign engine's honest subset must be named to be legal — and it is the v1 target for any port. Byte-shape change — must precede the exporter (D-γ).

- **D-028 (2026-08-06)** — **The ProgramIR is the product; ports target the IR, not the framework.** Hub-and-spoke: frontends produce IRs, engines execute them, optimizers are IR→IR with a score, evals are IR→score — all periphery, plural and disposable; the IR is the one stable center and dspy-Python is reference implementation #1, not the definition. Two grades per language: **grade 1 — hold** (parse/validate/version-check/link-check/diff/explain; a pure data library) and **grade 2 — execute** (adapter engine + lm15 + node-set interpreter). An optimizer needs only grade 1 plus an execute oracle *somewhere* — checkpoint = save makes propose→score→keep engine- and language-agnostic; scoring may be remote. Consequence: a third contract repo, **programir-contract** (manifest JSON Schema, forward-AST encoding with written operational semantics, link/load/refusal error codes, versions block, artifact corpus seeded by D-γ), is a first-class deliverable atop lm15-contract and the adapter-ir contract; grade-1 TS/Go libraries start the moment it exists; frontends are deferred indefinitely. *Why:* the same play that produced conformant lm15-go/ts, run at the top of the stack; it collapses the 3×3 author×engine matrix (every cell goes through the IR) and answers cross-language.md's posture question.

- **D-033 (2026-08-07)** — **Interpreter identity profiles are open and structural; execution support is separate.** Component 7's canonical entry declares `language`, exact `runtime {identity, version}`, `contract`, `namespace_policy`, `result_convention`, `vars_marshaling`, `packages`, `resource_limits`, and `isolation_floor`, plus receiver-controlled `placement`. - **D-034 (2026-08-07)** — **The node-set v0.2 ergonomics batch is ratified; `node_set` is `0.2`.** Admit-semantics/desugar-syntax governs: statements gain `SetIndex` and `AssignTuple`; expressions gain `IfExp`, `BoolOp`, `UnaryOp`, `Format`, `List`, `Dict`, `Index`; `For` gains list iteration (shallow snapshot at loop entry); `BinOp` widens to `add|sub|mult|div` under exact-int64 arithmetic with `InterpreterArithmeticError` (never wrap, never silently promote; Inf/NaN excluded; `mod` refused); `Compare` widens to orderings (mathematically exact numbers, code-point strings) and membership. Value model: containers are reference values under declared aliasing rules; strings are well-formed Unicode scalar sequences (lone surrogates refuse); ints are a distinct exact type to ±2^63−1; bool is never a number; Prediction records are read by `Attr` only. `InterpreterTypeError`/`InterpreterKeyError`/`InterpreterArithmeticError` become exact-matchable handler names; `LoopCapError`/`MalformedNodeError` stay uncatchable. versions.md gains the pre-1.0 rule that an implementation declares a *set* of supported exact versions (membership accepts), and `node_set` versioning independently of `ir_version` is settled by demonstration. Corpus and implementation catch-up (reference, go, ts, atomic pin bumps) are the named follow-on waves. *Why:* v0.1 proved the skeleton but cannot express an f-string, a dict literal, or `trajectory[key] = v` — the syntax census showed every real dspy forward uses all three; admitting the small semantic core and desugaring the rest keeps ports cheap while making forwards feel like normal code.

- **D-035 (2026-08-07)** — **The dspy-side node-set doctrines the v0.2 batch required.** (1) **The desugar table is the frontend contract**: independent frontends must lower the same surface construct to the same tree (f-strings → `Format`; tuples/destructuring → `List`/`AssignTuple`; comprehensions → For-over-list accumulation; `is None` → `eq null`; `AugAssign` → `Assign`+`BinOp`; `Assert` → `If`+`not`+`Raise InterpreterError`; chained comparisons only when interior operands are `Var`/`Const`, else refuse). (2) **`dspy.context`-scoped forwards are non-exportable**: `With` is ambient dynamic scoping — the zero-reach-back rule's target — and has no lawful lowering. (3) **Refine/BestOfN remain the refused module family** (`ClassDef`/opaque reward callables); the "try N, keep best" concept stays representable as a future metric-leaf lowering. *Why:* the contract owns the tree; what different authoring surfaces must agree on, and what is refused with a name rather than half-supported, are dspy-side commitments the contract's evidence rule requires recorded here.

- **D-037 (2026-08-10)** — **The node-set v0.3 values batch is ratified, with the aforward same-graph rule; `node_set` is `0.3`.** Admissions (contract `spec/node-set.md`, every row census-cited): `Slice` reads (Python clamping, negative indices, literal step ±1, no slice assignment); `Pass`; the `Log` statement as `print`'s lawful home (observability trace, never program state); a 12-name pure-builtin table (`len, str, int, float, max, min, sum, sorted, any, all, json_dumps, json_parse` — the JSON pair bound to the canonical serde profile); an 18-name value-method table (str `strip/lstrip/rstrip/lower/upper/split/join/replace/startswith/endswith`, list `append/extend/pop`, dict `get/keys/values/items/pop/update` — `update`'s ruling un-defers `BitOr` dict-merge as a desugar); the float-repr pin (shortest-round-trip decimal, JS exponent thresholds as law, `-0.0` → `"0"`); desugar additions (walrus, `%`-format, enumerate-For, print→Log, dict-merge). **The aforward rule:** `async def aforward` / `await leaf.acall(...)` lowers to the IDENTICAL graph as the sync twin — execution mode (sync/async/batched/parallel) is the engine's, never the artifact's; explicit concurrency (`gather`, tasks, locks) refuses at compile (1/389 in the user census), with a future explicit fan-out node as the only admission path. - **D-042 (2026-08-12, ratified by Maxime in session)** — **The isolation gradient: `placement.isolation` becomes an ordered 7-level vocabulary; floors bake, envelopes bind; sealed shared memory is the local data plane.** (1) The enum `none|os_sandbox|remote_sandbox` is replaced by the ordered, versioned vocabulary `none | namespace | fork | fork_cgroup | fork_ratchet | sandbox | remote` (spec §e0-isolation) — an axis orthogonal to the rung (rung = where the backend lives; isolation = how hard the wall is; most of the gradient refines rung 1). (2) OS mechanisms split into *revocable* knobs (cgroups, netns joins, broker grants, passed FDs — may change at leaf boundaries; a PID travels in/out of this half) and *one-way ratchets* (seccomp, Landlock, `no_new_privs`, UID drop — bind a PID for life), so at `fork_ratchet`+ process lifetime = leaf span: fork from the warm zygote parent (CoW-shared RAM), place, ratchet, run, exit. (3) Component 6 tool placement gains `isolation_floor`, mirroring the D-033 interpreter profile: the artifact bakes the author's *minimum* demand (an optimizer-authored body may demand no-ambient-network); the receiver's actual envelope is a binding, may exceed the floor, never under-runs it — under-floor is a loud refusal; composes with the D-040 trust gradient. (4) Local-rung leaf I/O travels as sealed shared memory (`memfd` + `F_SEAL_WRITE`, Arrow IPC) with the FD as the capability grant — immutable to hostile bodies, wall-crossing at zero isolation cost, zero-copy — closing D-027's open `vars`-marshaling surface as one contract over two transports (sealed-Arrow locally, JSON-typed wire remotely). (5) The isolation-invariance law: a leaf must behave identically at every level; behavior that changes under a level change indicts the leaf (undeclared side channels), keeping the gradient a binding, never an identity axis — scores stay warranted across isolation re-placement. (6) **Binding-level floors with max-composition**: a leaf's binding may carry an `isolation_floor` override; effective floor = max(entry floor, binding floor) — floors tighten, never loosen, per binding, so per-leaf trust distinctions (author's helper vs optimizer-generated body on the SAME runtime entry) never force a floor-fork of a byte-identical entry (§b-pools sharing-as-stated-fact preserved); `authored_by: optimizer` defaults the binding floor per the D-040 trust profile. (7) **Lowering a floor is an artifact edit, never an engine flag** — new artifact version, provenance records `floor_lowered_by`/date/old→new; raising the envelope stays a binding but is recorded per leaf in run provenance (View-2) and on scores (View-3), making invariance a checkable claim; declared grants are orthogonal to level (any envelope must supply them or load refuses — no silent runtime surprises). (8) **The gradient never changes the runtime**: every level runs the declared D-033 interpreter profile unchanged; a backend that cannot satisfy it (Pyodide/wasm lacking declared packages/threads/version) is an identity deviation handled by D-033 (refusal or score-detaching recorded deviation), never a higher isolation level — `remote` means the same profile satisfied elsewhere. *Why:* the ladder already reserved "same-sandbox subprocess" but the 3-value enum could not express the real gradient from one-RAM/one-process to full lockdown, had no floor semantics for optimizer-authored code, and left the local data plane undefined.

- **D-043 (2026-08-12, ratified by Maxime in session)** — **FlexIR trust knobs are floor declarations, not enforcement.** (1) The optimizer's `code_trust` knob migrates to the D-042 `isolation_floor` vocabulary — `"isolated"` ≙ a `fork_ratchet` floor, `"in_process"` ≙ `none`; the old values survive as reading aliases only. Optimizer-authored leaves default their BINDING-level floor mechanically via `authored_by: "optimizer"` through the D-040 trust profile — the optimizer never writes envelopes, only floors. *Why:* the knob always meant "how much do we trust this generated body," which is exactly what a floor states; keeping a parallel private vocabulary would fork the trust axis the gradient just unified (notes Q9, Q15). (2) Enforcement lives solely at the engine's materialize seam: the optimizer *declares* (floors, grants, authorship), the receiver's envelope *satisfies* — the same bake-a-floor/bind-an-envelope split D-042 rules for every leaf. The optimizer carries no sandbox code and no privileged path. *Why:* an optimizer that enforced its own isolation would be a second engine with a second security posture; one seam, one auditor (notes Q11–Q13). (3) With an enforced netns-empty envelope, the `lm_calls` cheapness channel becomes kernel-backed: a generated body physically cannot smuggle an LM call, so the measured cheapness is a fact, not an honor system. The import allowlist and `allowed_deps` demote to defense-in-depth plus teaching ergonomics — good error messages early, never the security boundary. *Why:* static allowlists rot and are bypassable by construction; the kernel's empty network namespace is neither (notes Q7, Q9 §4). (4) Egress for below-full-trust leaves goes through a parent-owned broker proxy: hostname allowlist, per-request log, and credential INJECTION — the broker attaches `Authorization` on the way out, so secrets never enter the sandbox and generated code cannot leak a key it never held. This supersedes env-passed credentials for untrusted leaves. *Why:* IP allowlists rot under anycast/CDNs, and a key in a sandbox's environment is a key already leaked to the code inside it (notes Q7). (5) Optimizer trajectories and score records carry the scoring envelope per candidate — the D-042 point-(7) run/score provenance applied to optimization: every candidate's score names the isolation it was measured under. A behavior divergence across isolation levels is a **candidate refusal class**: the invariance law indicts the candidate (undeclared side channels), and the optimizer discards it as defective, not unlucky. *Why:* candidates compared under unrecorded envelopes make cheapness and correctness incomparable; and a candidate that only works at `none` is exactly the artifact the floor exists to catch (notes Q13, Q9 §4). (6) Interpreters and tools unify as one **leaf substrate**: a shared record shape with a closed `kind` discriminant for invocation semantics (`call` — one request/response — vs `session` — a held stateful context), and grants as a closed static effect row (FDs, broker routes) readable from the manifest without executing anything. Session leaves at `fork_ratchet`+ are fork-scoped — lifetime = leaf span, per D-042's ratchet rule. Nested cost attribution: an `lm_calls` made through a grant bridge attributes to both the session leaf that made it and the underlying predictor it reached, transitively, so cheapness accounting survives nesting. *Why:* the interpreter/tool split was always two spellings of "a leaf that executes a body under a profile" — D-033's structural profiles and D-042's floors apply to both identically, and the census showed every knob (floor, grants, placement, authorship) landing on both; one substrate makes the FlexIR edit vocabulary (replace predict with code leaf) target one shape, and static grant rows keep the whole trust surface auditable without simulation (notes Q7, Q15, Q16).
